# SponsorFit Web Demo Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a polished, shareable SponsorFit web demo that gives open-source maintainers a lightweight repository preview and converts interested visitors into GitHub stars and Skill/CLI users.

**Architecture:** Add a self-contained Next.js App Router application in `web/` so the existing zero-dependency Python package remains unchanged. A Route Handler accepts a strict GitHub repository identifier, fetches public repository metadata and README content from GitHub, and runs deterministic TypeScript heuristics. Static case-study routes demonstrate the product without depending on live API availability, while report URLs re-run the lightweight preview from a shareable query string.

**Tech Stack:** Next.js 16, React 19, TypeScript, CSS, Node's built-in test runner, GitHub REST API.

### Task 3: Add the GitHub analysis Route Handler

**Files:**
- Create: `web/app/api/analyze/route.ts`

**Steps:**
1. Accept only a small JSON body containing `repository`.
2. Apply best-effort per-instance rate limiting.
3. Fetch only constructed `api.github.com/repos/{owner}/{repo}` endpoints.
4. Convert GitHub 404, rate-limit, and upstream errors into useful responses.
5. Return cacheable preview JSON with explicit observed/inferred/hypothesis labels.
